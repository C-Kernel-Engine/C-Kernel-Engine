v8 Vision Capability Status

Artifact-specific status for generated image execution. Encoder numerics, decoder numerics, task quality, and live serving are separate gates. A passing shared-prefix decoder test does not certify image preprocessing or the encoder.

Evidence reviewed: 2026-11-06. This is a curated snapshot, not a live nightly result. Links identify the result and its scope; a newer build needs its own evidence.

No full vision artifact is certified for the HTTP harness yet. Generated image paths run, but independent numerical, task-quality, and live-serving gates have not all passed on one pinned artifact. Unsupported bundles should continue rejecting image requests.

Experimental Qwen3-VL image HTTP adapter

The separate server.vision_http service connects uploaded PNG/JPEG bytes to the existing generated encoder and visual native-session entry. Ordinary text serving remains unchanged. It binds only to loopback. Its supported surface is /v1/chat/completions, streamed or non-streamed, with exactly one image across the caller-supplied conversation. Tools, PDFs, remote image fetching and additional images are explicitly unsupported. A PDF must first be rendered into page images by the client; this first endpoint handles one page per request.

One request owns admission before upload starts; other requests receive 429. Uploads are bounded at 12 MiB and 30 seconds, image bytes at 8 MiB, decoded pixels at 16 million, text at 64 KiB and output at 1,024 tokens, further restricted by the generated context capacity. Each request uses a fresh subprocess with a 32 GiB address-space limit. This is not resident serving or batching. Cancellation kills and reaps that worker before releasing admission. A streaming response supplies X-Request-ID; cancel it with DELETE /v1/requests/{id}. Closing the client connection also cancels work. Healthy native execution has no automatic inference deadline.

Pin operator-owned generated artifacts before launch. The decoder directory needs libmodel.so, its packaged engine/tokenizer, weights, layouts and imported publisher chat_template.jinja. The profile hashes these inputs, the GGUF tokenizer source and the native session library. Artifact changes require explicit re-pinning; rebuilding a bundle does not silently upgrade the running profile.

The client example uses only Python's standard library and can be copied to another machine. Connect through SSH forwarding for remote use. No unauthenticated remote listener is provided. Capabilities describe preflight validation, not full numerical certification. Startup loads and frees both native models; workers verify pinned artifacts again for every request.

The November 14 P3 smoke test uses a generated 56-by-56 two-color fixture, four visual rows, 20 prompt rows and only 256 tokens of compiled capacity. Both response modes produced the same four tokens and first full-vocabulary logit hash as retained standalone execution. This is a budget- truncated output, not an answer-quality or normal-EOS pass. Rejection, busy admission, cancellation and follow-up recovery were exercised separately. Cold request cost includes hashing and loading; these timings must not be presented as warm resident performance. See the retained scope and evidence.

Next gates: larger pinned context and image geometry, complete answers, repeated image/follow-up trajectories, disconnect stress, then a real harness task. Independent encoder accuracy remains a separate open gate. Stop this isolated service to roll back; it does not replace text or speech services.

Repeatable image answers and follow-up acceptance

Cancellation now retains ownership while subprocess creation finishes, then reaps the child before releasing admission. The delayed-creation regression fails against the previous controller and passes with this change; test cleanup also reaps its deliberate negative-control child. A failed transport before stream iteration also releases admission, and nested generators close before a new request can start. The CLI allows five seconds for graceful server shutdown before cancelling active requests; this does not impose a normal inference deadline.

The acceptance lane uses committed two-color PNG/JPEG fixtures, swapped left/right colors, repeated requests and caller-supplied follow-up history. The assessor requires the requested JSON answer and normal stop; a truncated answer, swapped colors, duplicate JSON keys, extra contradictory text, reused request ID or service restart cannot pass. Every attempt gets its own report directory; it starts INCOMPLETE and preserves responses collected before a failure. A timeout is INCOMPLETE, not a model-quality verdict. This command is suitable for an opt-in local nightly; no timer is installed and no old result is substituted for a current attempt.

For a stronger connection check, launch the isolated test service with --verify-reference. This operator-only flag repeats direct generated prefill using the identical rendered IDs and encoded prefix before native-session execution. Initial full-vocabulary logits must match exactly. It doubles prefill work and is intended for diagnosis, not performance measurement. The independent encoder oracle, later decode logits and full mutable-state comparisons remain separate gates.

These simple color tasks do not establish OCR, arbitrary visual reasoning, tools, real harness integration, resident latency or sustained unattended operation. Native visual session: first connected decoder boundary

The next experimental step adds ck_session_v8_generate_visual and SessionV8.generate_visual. One already-encoded visual block sits between exact rendered token segments. The existing generation lock, decoder loop, token callbacks, cancellation flag and failure reset remain the execution owner. That native change alone did not add HTTP serving; the experimental adapter above now connects it. It is not a resident encoder service.

The generated decoder exports its exact visual-row width, including any deep-stack slices. Older bundles without that contract reject this entry. Native admission checks token IDs, finite visual values, buffer extent, grid geometry, explicit text position, sampling parameters and both requested and loaded context capacities before reset. Failed or cancelled execution resets the affected state. Visual requests do not publish text checkpoints or enable prefix reuse. The Python binding owns a prefix copy during execution; its storage must be included in the future HTTP memory budget.

A fresh Qwen3-VL-8B-Instruct Q4_K_M decoder and BF16 vision projector processed a generated 56-by-56 image into four visual rows of 16,384 floats, with 20 total prompt rows. Three native session repetitions matched direct generated execution for all four full-vocabulary logit rows, active positions and declared KV arenas. KV comparison includes arena padding; internal bridge scratch is not captured. This establishes same-artifact session equivalence, not an independent encoder oracle, OCR accuracy, long-context or harness certification. Four-token generation stopped at its requested budget.

The first real load exposed a deployment gap: standalone bridge libraries relied on a globally preloaded tokenizer. The bundle compiler now links and packages that dependency, hashes it in the build fingerprint, and invalidates old compile stamps. A fresh-process relocation test covers this defect.

Retained native evidence and limitations. The opt-in replay command consumes an existing bridge report and its exact prefix/logit captures:

python version/v8/scripts/certify_visual_session_v8.py   --bridge-report /path/to/bridge_report.json   --prefix-f32 /path/to/prefix.f32   --reference-logits-f32 /path/to/logits.f32   --output /path/to/current-session-report.json

The probe writes INCOMPLETE before starting and FAIL on missing inputs or an execution error. It verifies actually loaded library hashes. Synthetic compiled tests separately exercise A/B/A, failed prefill, invalid admission without mutation, cancellation, close ownership and successful follow-up. They are not model arithmetic certification. These native tests remain separate from the HTTP smoke evidence above.

The experimental HTTP adapter above connects this boundary for one pinned bundle. Larger-context task acceptance and image-plus-tool continuation remain open. Ordinary text and speech services are unchanged.

Experimental serving integration: upload contract first

As of 2026-11-13, the ordinary HTTP session still rejects live images. The generated standalone bridge already executes image preprocessing, encoder, visual prefix and decoder, but the complete upload/encoder/session path is not yet exposed through HTTP. The first serving change adds server.vision_input.prepare_vision_input: a model-independent, ordered input contract. This is a callable validation helper, not a new HTTP endpoint or a claim of harness acceptance.

The harness owns local file access. It must read an explicitly selected file and upload its bytes as a PNG/JPEG base64 data URL. A filename on the laptop is not a filename on P3. The helper accepts Responses input_text/input_image and Chat Completions text/image_url parts and preserves their order and original image bytes. It does not flatten images into text, resize them, fetch URLs, read server paths, or modify publisher templates. Model-specific preprocessing remains in the generated pipeline.

Initial defaults allow one image, 8 MiB total compressed image data, 16 million decoded pixels, 64 KiB of UTF-8 text and 32 ordered parts. These are input-safety bounds, not a bundle's token capacity or supported visual geometry. Future HTTP integration must additionally bound raw body size and concurrent uploads before JSON parsing. Animated images, PDF, audio/video parts, remote URLs, file IDs and explicit image detail modes are rejected until their own contracts exist.

  1. Pin and rebuild one Qwen3-VL encoder/decoder pair with loaded library, tokenizer and preprocessing identities.
  2. Expose generated mixed-image/text execution through a checked native session adapter. Bind visual rows, positions, masks and any deep-stack inputs to their owner. Reject unsupported order/geometry before mutation.
  3. Use the upload contract at HTTP admission only for a bundle declaring the connected capability. Validate visual plus text plus output capacity; serialize native ownership and keep prefix caches disabled until certified.
  4. Compare identical image bytes and rendered tokens through standalone and HTTP execution, including full logits and applicable state. Exercise reset, cancellation, streaming and a successful follow-up.
  5. Connect a real harness, then add image-plus-tool continuation and explicitly tested multi-image ordering.

The server suite covers malformed images, MIME mismatches, truncation, aggregate limits, part order, Unicode, request independence and rejection before expensive decoding. It also retains the live-media rejection tests. These are admission tests, not encoder parity tests. Qwen Code, Nemotron harnesses and other clients gain image support only for an explicitly supported vision artifact; text-family support alone is insufficient. PDF rasterization and its page/pixel limits belong to a separate follow-up.
