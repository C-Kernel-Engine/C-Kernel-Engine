Test Report Versions

Parakeet TDT Native CPU Bring-up

CKE converts the pinned nvidia/parakeet-tdt-0.6b-v3 checkpoint to BUMPWGT5 and transcribes a 7.435-second WAV entirely with native CKE kernels — 50/50 token IDs and 50/50 durations exactly match the pinned Transformers FP32 reference. The certified scope is that one clip; long audio, multilingual speech, resampling, timestamps, streaming, and diarization remain untested or out of scope.

Current claim boundary
Reference fixture: passed. Native conversion and end-to-end transcription: passed on one 7.435-second English, mono, 16 kHz PCM WAV, exact at token-ID and duration level against the pinned reference. Long audio, multilingual speech, resampling, silence robustness, word-level timestamps, streaming, concurrent sessions, and diarization: not tested. Orchestration is a Python ctypes driver over native CKE kernels and BUMP weights; a generated-C Parakeet artifact does not exist yet.

How audio becomes text

The pipeline has four compute stages plus a decode state machine, all declared in the circuit version/v8/circuits/parakeet_tdt.json and executed by run_parakeet_native_v8.py, which calls native providers through libckernel_engine.so and libckernel_audio.so. The frontend turns PCM samples into 128-bin log-mel frames; three stride-2 grouped Conv2D stages subsample 743 live frames to a 93×1024 token grid; 24 FastConformer blocks and a 1024→640 projection produce the 93×640 encoder memory; the transducer loop then walks that memory frame by frame.

TDT decode: blank handling and time advancement

The greedy loop in ParakeetSession.decode holds an LSTM hidden/cell state, a current token (initially blank 8192), a reused decoder projection cache, and a frame index into the 93-row encoder memory. Each iteration:

  1. Prediction network, conditionally. The two-layer LSTM is stepped only when the previously emitted token was nonblank (or on the first iteration). After a blank, the cached decoder projection is reused unchanged — blank frames do not advance the language-model state.
  2. Joint. The current encoder row and the decoder projection are summed, passed through ReLU, and projected to 8,198 logits: 8,193 token logits (vocabulary 0–8191 plus blank 8192) followed by 5 duration logits.
  3. Two independent argmaxes. The token is the argmax of the token logits; the duration is durations[argmax(duration_logits)] with the checkpoint's table [0, 1, 2, 3, 4].
  4. Advance rule. If the token is blank and the predicted duration is 0, the duration is forced to 1 — a blank may never freeze the loop. A nonblank token with duration 0 is legal and holds the frame (multiple symbols on one encoder frame, bounded by max_symbols_per_step = 10). The frame index then advances by the duration.
  5. Termination. The loop stops when the frame index reaches 93 (the encoder length). A hard bound of 10 × 93 = 930 steps raises TDT decoder exceeded its encoder-derived step bound instead of looping forever.

Worked example from the recorded native trajectory (see the diagram strip): the first two steps are blanks — step 1 predicts duration 0, forced to 1; step 2 predicts duration 4, skipping frames 1–4 (leading silence). Step 3 emits token 499 at frame 5, and only then does the LSTM step. Across the clip, 6 of the 50 recorded entries are blank (including the initial state), 44 are emissions, and the durations sum to exactly 93 frames × 0.08 s = 7.44 s of coverage for the 7.435 s clip. Token timestamps are derivable as cumulative duration × 0.08 s, but the native runner does not emit them and does not reproduce the reference processor's punctuation-collapsing rule.

Runbook: reproduce the certified path

Supported checkpoint. Exactly one: nvidia/parakeet-tdt-0.6b-v3 revision 541d1f99...defd82b (CC BY 4.0), converted with --arch parakeet_tdt --dtype fp32. Other revisions or dtypes are outside the certified claim.

Input requirements. Mono, 16 kHz, 16-bit PCM WAV (RIFF). Anything else is rejected with Parakeet frontend currently requires mono 16-bit PCM WAV at 16000 Hz; normalize first, e.g. ffmpeg -i in.mp3 -ac 1 -ar 16000 -c:a pcm_s16le out.wav. The committed fixture version/v8/test_assets/parakeet_tdt_0_6b_v3/2086-149220-0033.wav is the certified input.

Step 1 — download the pinned checkpoint (cold, once, ~2.4 GB):

hf download nvidia/parakeet-tdt-0.6b-v3 \
  --revision 541d1f99c6b0c3cd0b11a95167540bb8edefd82b \
  --local-dir .ck_models/parakeet-tdt-0.6b-v3

Step 2 — convert to BUMPWGT5 (cold, once): writes weights.bump (2,508,517,458 bytes in the recorded run), config.json, and weights_manifest.json. Conversion time is one-time setup cost and is excluded from the warm transcription timings below.

python version/v8/scripts/convert_safetensors_to_bump_v8.py \
  --checkpoint .ck_models/parakeet-tdt-0.6b-v3 \
  --output .ck_build/parakeet-tdt-0.6b-v3/weights.bump \
  --config-out .ck_build/parakeet-tdt-0.6b-v3/config.json \
  --manifest-out .ck_build/parakeet-tdt-0.6b-v3/weights_manifest.json \
  --arch parakeet_tdt --dtype fp32

Step 3 — build the native libraries (cold, once per checkout):

make build/libckernel_engine.so libckernel_audio.so

Step 4 — run transcription (warm):

python version/v8/scripts/run_parakeet_native_v8.py \
  --model .ck_build/parakeet-tdt-0.6b-v3 \
  --audio version/v8/test_assets/parakeet_tdt_0_6b_v3/2086-149220-0033.wav \
  --fixture docs/notes/artifacts/parakeet_tdt_0_6b_v3_2086-149220-0033_fp32.npz \
  --decode --output .ck_build/parakeet-tdt-0.6b-v3/native-e2e.json

--fixture and --decode turn the run into a certification: without them the runner still transcribes but has nothing to compare against. --stop-after-layer -1|0|23 bisects the encoder against fixture boundaries for debugging.

Output format. The report ("kind": "cke.parakeet.native_e2e") records runtime-library and weight SHA-256 provenance, per-stage seconds, frontend/encoder/first-logit RMSE comparisons, the full token-ID and duration sequences, the first divergent index for each, the detokenized transcript, a checks map, and an overall "status": "pass". The recorded evidence is the committed native E2E report.

Expected evidence and warm timing. On the recorded run (commit 909a2c164, PR #504, Ryzen 9 9950X3D per the README evidence table, FP32, workload = the 7.435-second fixture; the report JSON records platform and Python 3.14.4 but not thread count): frontend 0.069 s, encoder 1.027 s, total run 2.25 s including hashing, decode, and tokenizer work that sit outside the two stage timers — roughly 3.3× real time for this single short clip, not a throughput or streaming claim. Expected output transcript: “Well, I don't wish to see it any more, observed Phoebe, turning away her eyes. It is certainly very like the old portrait.”

Verification status of this runbook. The checkpoint is not in the local model cache on this machine, so the commands above are verified-by-CI/evidence, not re-executed here: argument names are checked against the scripts' argparse definitions, and the expected outputs are the committed artifacts. Ordinary CI coverage is make test-audio (which runs unittest/test_audio_encoder.py PyTorch oracles for the five new providers) and make test-audio-v8-contracts (which runs tests/test_v8_parakeet_inventory.py). The full checkpoint E2E itself has no nightly job; the committed E2E report is cached Ryzen evidence from the PR #504 validation run.

First reference fixture

The 7.435-second mono 16 kHz utterance 2086-149220-0033.wav is the sample linked by NVIDIA's model card and comes from the CC BY 4.0 LibriSpeech corpus. On Ryzen with PyTorch 2.13.0+cpu, 16 threads, and the pinned Transformers commit, the reference completed in 0.39 seconds and produced 50 decode steps, 44 nonblank emissions, durations, and token timestamps.

New production compute paths must use planner-declared scratch or session-owned state. They may not allocate or free heap memory per call, hide allocation in helpers, substitute large stack buffers, or share mutable scratch across sessions. The five new providers follow this: attention uses one caller-owned T-element score row; the LSTM uses caller-owned 4H gate scratch and session-owned state (guarded by tests/test_v8_parakeet_native.py::test_new_compute_kernels_do_not_allocate_or_free).

Reproduce the reference capture

Download the exact Hugging Face revision once into the shared model cache, then run the fixture tool. Transformers, PyTorch, librosa, and soundfile belong to this certification environment; the CKE inference path does not depend on them.

export CKE_MODEL_CACHE="$HOME/.cache/cke/models"
hf download nvidia/parakeet-tdt-0.6b-v3 \
  --revision 541d1f99c6b0c3cd0b11a95167540bb8edefd82b \
  --local-dir "$CKE_MODEL_CACHE/parakeet-tdt-0.6b-v3-541d1f99"

PYTHONPATH="$HOME/.cache/cke/reference/transformers-66799f45" \
