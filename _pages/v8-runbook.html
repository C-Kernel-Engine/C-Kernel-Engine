Use the notebook as an experiment controller

  1. Launch Jupyter from the repository root and open the v8 notebook path shown above.
  2. Run the model and preflight cells first. Inspect the authored semantic graph, parameter count, forward/backward requirements, and candidate-map rows before allocating a training run.
  3. Leave EXECUTE_TRAINING = False while changing the circuit, corpus, tokenizer, or numerical contract. Set it to True only when can_launch_generated_workflow is true; only the completed workflow can produce a PASS. The equivalent environment switch is CKE_NOTEBOOK_EXECUTE=1.
  4. Use DatasetConfig to point at a pinned corpus and bounded train/validation token counts. Keep the model vocabulary equal to TokenizerConfig.vocab_size.
  5. Use 4, 5, 6, or 10 layers and supported dense/GQA head geometry. The graph controls depth, dimensions, ordered block identities, vocabulary, and a finite positive global rope_theta. In this uniform topology, reordered labels establish authored identity order; they do not claim executable support for nonuniform block reordering. Stage 1 fixes SwiGLU, RMSNorm epsilon 1e-6, bias-free projections, normal_0p02 initialization, and FP32; other values fail before weight initialization.
  6. Inspect python_training_semantic_model.json after preflight. Confirm that its parameter contract, ordered layer trace, and hash match the training report. The workflow rejects missing, changed, or mismatched semantic artifacts.
  7. After execution, inspect the exact tokenizer round trips, training and held-out loss curve, optimizer-step parity curve, worst per-tensor differences, exact restart result, and multi-token inference-export result.
  8. Open RUN_DIR / "ir_report.html" from the notebook for the dataset, tokenizer, forward/backward stitching, saved tensors, memory, checkpoint, and export panels. Set EMBED_IR_VISUALIZER = True to place that report inside the notebook.
  9. Set LOAD_EXISTING_REPORT = True only for exploration. This path is read-only: it does not call preflight or replace the original experiment definition. The notebook validates the saved manifest and labels missing or mismatched evidence explicitly.
  10. Use training_workflow.json as the machine-readable verdict. A generated HTML file alone is not a PASS.

What Full-Model Certification Means

Full-model certification is not defined by an arbitrary answer length. A 100-token response, a 5K context, coherent prose, or one matching top-1 token can establish bring-up evidence, but none certifies the complete model. CKE promotes evidence in three levels:

LevelRequired evidenceWhat it does not prove
Bring-upReal weights convert, compile, and execute coherently through the intended runtime path.Numerical agreement, advertised capacity, quality, or performance.
Full-model numericalExact tokenizer or processor inputs; complete tensor inventory; every executed layer kind and persistent-state transition compared with an independent oracle; final-logit agreement; and at least 128 deterministic decode steps under a declared exact or tolerance contract.Maximum context, broad application quality, every ISA, or competitive speed.
ProductionFull-model numerical evidence plus the advertised context or media envelope, repeatability, memory-plan safety, supported ISA coverage, application fixtures, and recorded performance.Unmeasured hardware, quantizations, languages, or workloads.

The model and kernel matrix records the strongest level reached by each family. The kernel-map guide explains how the selected providers own their arithmetic and call ABI. The X-Ray guide covers layer and operation comparison, and numerical contracts defines exact and tolerance-based provider evidence.

Idle-host local nightly

GitHub and local hardware use the same scripts/nightly_runner.py test and evidence engine. GitHub builds in its workflow; each clean local worktree passes --prepare so build preparation is recorded in the nightly report. The local coordinator only admits a registered profile when measured load, available RAM, and free disk satisfy its tier. The checked schedule runs the portable profile first, then progressively admits full, demo-readiness, and high-capacity evidence on larger hosts. 

python3 scripts/idle_nightly_coordinator.py \
  --repo /srv/cke/C-Kernel-Engine \
  --ref origin/main --fetch \
  --state-dir /srv/cke/nightly-state \
  --list

Each cron invocation runs at most one due profile. Results are atomic and keyed by the source commit, case contract, compiler, physical-core selection, tracked environment, and registered manifest hashes. A zero process exit becomes PASS only when the fresh report matches the attempt and commit, reconciles its summary, contains its complete declared execution inventory, and has no unexpected skips. On restart, a stale RUNNING attempt becomes INTERRUPTED before another attempt begins. Every child is restricted to one logical CPU per physical core, and the common CKE, OpenMP, OpenBLAS, and MKL thread limits match that physical-core count. 

*/10 * * * * cd /srv/cke/C-Kernel-Engine && /usr/bin/python3 scripts/idle_nightly_coordinator.py --repo /srv/cke/C-Kernel-Engine --ref origin/main --fetch --state-dir /srv/cke/nightly-state >>/srv/cke/nightly-state/cron.log 2>&1

Reserve the host before interactive work by creating /srv/cke/nightly-state/PAUSE. The coordinator terminates and reaps only its owned process group, records the profile as INTERRUPTED, and retries it from the profile boundary after the reservation file is removed. Admission checks free swap as well as load, RAM, and disk; a running profile also interrupts on sustained swap activity or loss of its configured memory reserve. Use --rerun only to ignore cadence. The --exclusive option bypasses the idle-load check for a deliberately reserved host, but it does not bypass pause, memory, disk, or swap safety. This is profile-level recovery; it does not claim per-test or mid-inference checkpointing. 

touch /srv/cke/nightly-state/PAUSE
# use the host, then allow scheduled work again
rm /srv/cke/nightly-state/PAUSE

Run only trusted refs such as origin/main. The coordinator creates a detached per-commit worktree, loads the checked schedule from that commit, reuses model caches outside the worktree, retains at most two coordinator-owned worktrees by default, and never resets the operator checkout. Contributor PR code must use an isolated approval path without credentials or writable private corpora.

This coordinator currently owns one host and one local ledger. P3/Ryzen pooling requires bounded runner cases plus an authoritative lease service with host capabilities, attempt fencing, and combined reporting; independently pointing both hosts at one JSON ledger is unsupported.

New Model Compatibility Workflow

  1. Start with safetensors when available. Convert safetensors to BUMP and compare CK against PyTorch with BF16/FP32 weights. This isolates graph stitching, RoPE placement, activation math, and layer contracts before quantization enters the picture.
  2. Then bring up GGUF. Convert GGUF to BUMP and compare CK against llama.cpp. This catches tokenizer/template behavior, tied versus untied heads, quantized projection layouts, and stop-token policy.
  3. Only optimize after parity is understood. Once BF16/FP32 graph parity and GGUF coherence are clean, profile Q4_K/Q5_K/Q6_K/Q8_K kernels and threadpool scheduling separately.

Gemma4 followed this route: BF16 safetensors proved the split-direct RoPE circuit against PyTorch, then the GGUF Q4_K_M path reused the same IR/kernel contract for coherent long-answer smoke testing.

Qwen3.6 Q4_K_M Optimized Prefill

PR #277 landed an exact batched-prefill optimization lane for Qwen3.6-27B Q4_K_M (merge c0a04690, engineering note docs/notes/QWEN36_EXACT_BATCHED_PREFILL_2026-07-30.md). It provides two principal optimizations:

  1. Exact head-parallel DeltaNet prefill. Independent value heads are partitioned across the threadpool once per prompt, and each worker advances its assigned heads through the tokens in order. This preserves CKE's certified serial arithmetic while avoiding serial head execution and repeated per-token dispatch.
  2. AVX-512 VNNI x16 Q4_K prefill projections. The existing Q4_K x Q8_K AVX-512 VNNI x16 provider is used for the measured Qwen3.6 prefill projection shapes, and the packed weights are prepared during model loading instead of being charged to the first prompt.

Troubleshooting

  • If you omit --image-path, the bridge uses a synthetic image path. That is useful for seam probes, not for validating real-image captioning.
  • If the bridge report is missing, check disk space first. The first compile path writes large intermediate artifacts.
  • If output starts echoing raw chat markers or thinking-control strings, keep --chat-template auto and do not force a manual template override on this model.
  • If captions are incoherent again, verify that the decoder GGUF and mmproj GGUF are the matching Qwen3-VL pair.
