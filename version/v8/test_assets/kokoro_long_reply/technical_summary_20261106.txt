PR 1035 is open and its merge conflict is fixed. The branch now includes current main's newer kernel-map counts, and the diff against main contains only the recurrent snapshot optimization. The updated branch is mergeable. Final-head required checks have restarted and are still running.

What PR 1035 does: the experimental two-request recurrent decode path from merged PR 1029 shares one generated Qwen3.8 QKV projection. To keep each request separate, it saves live intermediate values while switching between rows. The combined runtime reserves activation memory for long prefill prompts, so the old batch entry unnecessarily copied those full prefill-sized buffers for a one-token decode step. PR 1035 carries the separately planned decode-row sizes into the compiler's safety check. It uses them only when the buffer definitions, lifetimes, ownership, aliasing, and capacity match the combined arena. Otherwise the optimization is rejected.

On the pinned diagnostic Qwen3.8 bundle, batch workspace fell from about 1.67 gigabytes to 215 kilobytes. Planned snapshot copying fell from about 2.66 gigabytes to 325 kilobytes per step. Both row orders still match isolated execution exactly for full logits, positions, and complete KV, convolution, and SSM state. Cancellation, stale-handle rejection, slot reuse, and survivor continuation passed. After merging current main, 141 affected tests and 2,634 subtests passed locally.

This does not enable recurrent HTTP batching or change ordinary Qwen Code serving. Only one recurrent projection group is shared. Short warm Ryzen timings were roughly level with two isolated decodes, so there is no proven speedup yet. Merge PR 1035 only after its new final-head required checks pass.

The next serving milestone is a single reliable request path. A user should submit a question, receive a response, and see an explicit error when an artifact is unavailable. The server must retain the selected model, tokenizer, circuit, and provider identities for every run. Warm latency matters more than an isolated matrix benchmark because loading, scheduling, and output delivery all affect the user. The team will compare Qwen and Gemma with the same prompt set and record failures by stage. If a numerical result changes, we will replay the first divergent operation with identical inputs before altering any tolerance.

Speech work has a similar boundary. Kokoro can already convert supported phoneme requests into a complete waveform through generated C. The text frontend converts ordinary English into bounded requests, and a native worker can keep the model loaded across the chunks of one reply. The real question is whether those chunks remain clear, ordered, and responsive for a long technical update. A successful WAV header does not prove that a listener understands every number or model name. The current trial therefore records the original text, each spoken source span, the generated audio duration, and the result from an independent speech recognizer.

For a long document, the controller checks the entire source before beginning playback. It divides the text at sentence or whitespace boundaries, then asks the pinned frontend to plan each window. Every chunk retains its original character offsets. If the frontend cannot pronounce a symbol, the request fails with the affected span instead of silently dropping it. The playback queue remains bounded, so the process does not hold minutes of audio in memory. A durable checkpoint records only completed chunks. After an interruption, the next session may repeat an unfinished sentence, but it should never skip a completed one.

The voice session must also be predictable when the user changes direction. A stop request should silence the current audio without waiting for another model call to finish. Replacement should invalidate any queued output from the older reply. A later request should still work with the same loaded model and clean request state. Pause and resume belong to playback control, while native cancellation may occur at the next supported computation boundary. These are separate timings. The trial should report the audible stop delay, the native release delay, the first playback launch, and the total time for the spoken response.

Vision and speech should eventually form a stronger regression loop. A synthetic image can contain a known line of text, giving the vision model a hard reference. Its actual extracted text then becomes the input to speech generation. The resulting audio goes to a generated transcription runtime, and each boundary is checked independently. If the image says forty two but vision reads forty seven, a later matching transcript does not repair the vision error. The report should retain the image truth, vision output, spoken text, audio hash, and transcript, along with the exact model versions used.

Gradients still need to flow through frozen operations when they lead to an earlier trainable adapter. A small nonzero example can compare every forward output, input gradient, parameter gradient, and optimizer update against an independent reference. Save and resume tests then check that moments and weights persist exactly. The team should continue to measure performance at the complete request level. A fast convolution is useful only if the selected provider executes in the generated graph and reduces end-to-end time. The profile should separate text planning, model loading, operator groups, file writing, and playback. It should also record peak memory and variability across repeated warm requests. If synthesis takes longer than the audio it creates, buffering can shorten the first wait but cannot sustain uninterrupted listening indefinitely.
