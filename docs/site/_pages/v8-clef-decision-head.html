Indexed scoring gradients: separate normalization contracts

The final scoring branches now have checked FP32 derivatives for indexed pair features [a, b, a·b, |a−b|], normalized-vector dot products and cosine similarity. Owner indices route each option to its question. Repeated owners accumulate contributions; unreferenced owners receive zero. Both public gradient buffers are published only after all checks and reductions succeed. Caller-owned scratch holds groups·channels + 2·rows·channels floats; there is no kernel allocation.

Forward equivalence does not establish backward equivalence. The pinned head uses normalize-and-dot for its prior score and cosine_similarity for its joint score. PyTorch 2.12.1 normalization has a zero clamp derivative below epsilon, whereas its cosine implementation clamps a cloned norm under NoGrad and retains the norm derivative below epsilon. The new providers encode those policies separately. At zero norm, the norm VJP is zero; the direct numerator derivative still flows. At the normalization clamp boundary the derivative is one. Absolute difference uses zero subgradient at equality, including signed zero.

Consequently the cosine provider's below-clamp VJP deliberately matches the pinned framework's backward convention, not the finite-difference derivative of its clamped forward function. Central differences are tested away from nonsmooth/clamped boundaries; separate autograd tests cover zero, below epsilon, equality and adjacent FP32 values on both operands. Future head backward authoring must select the explicit derivative contract. Neither forward provider identity nor epsilon alone selects it.

The model-neutral regression executes one generated forward entry for span pooling → erf GELU → grouped pooling, then one generated backward entry for the reverse chain. Only native-produced forward intermediates enter that backward entry. This is an explicitly authored VJP circuit, not automatic backward synthesis through cke.v8.compile. It does not contain trainable parameters, a loss, optimizer updates, or the remaining complete-head derivatives.

  • Span gradients sum all overlapping contributions in ascending span order with FP64 accumulation. Unreferenced valid tokens become zero; inactive token rows and padding remain unchanged.

BF16-storage backward providers

The same three VJPs now also have explicit BF16-storage maps. Saved floating-point operands, incoming gradients and outgoing gradients use BF16; spans/counts remain INT32. Caller-owned FP32 workspace expands BF16 operands exactly, invokes the existing FP32 VJP arithmetic, then rounds each output gradient to BF16 using round-to-nearest-even. The FP64 reductions and FP32 intermediate stores inside the FP32 providers are preserved. There is no intermediate BF16 rounding inside a VJP.

This is a particular mixed-precision derivative contract, not a claim of parity with an arbitrary BF16/autocast forward graph. Grouped probabilities are recomputed using the existing FP32 forward semantics on expanded BF16 saved operands. Independent autograd runs FP32 computation on identical dequantized operands and rounds its gradients to BF16. The tested gradients match that oracle exactly after rounding; this is not a universal bit-identity guarantee.

Element counts and row strides use the pointed-to dtype, not bytes. BF16 buffers require two-byte alignment; INT32 spans/counts and FP32 scratch require four-byte alignment. Outputs and scratch must be disjoint from all reads and each other. Input padding is ignored, output padding/inactive rows stay untouched, and rejected calls publish no outputs. In particular, a finite FP32 gradient that rounds to BF16 infinity rejects the call before either grouped gradient is published.

The model-neutral generated backward entry composes all three BF16 providers through ordinary maps, lowering and memory planning. Tests include odd channel counts, unequal/singleton groups, ordered oracles at O0/O3, exact/one-short capacities, two-byte-aligned buffers, mixed-width partial overlaps, nonfinite input, FP32 and BF16-only overflow, RNE midpoint ties, subnormal values, final-operation failure propagation, and A→B→A recovery. Saved inputs in this test are synthetic; this does not execute a complete BF16 Clef forward/backward pair. PyTorch absence skips only the independent autograd test.
