Clef-Flash decision-head bring-up

Model topology lives in the circuit builders here. Kernels implement arithmetic; maps describe ABI, scratch and numerical contracts. Generic operation catalogue entries do not inspect the model name.

BF16 training prerequisites: storage admission now fails closed

Complete BF16 head training remains unsupported. Released-head FP32 training passes, but the shared training runtime still hydrates, snapshots and optimizes floating tensors as FP32. The planner recognizing a two-byte BF16 dtype does not establish a typed runtime ABI.

A controlled pre-fix reproduction supplied an FP32 layout and marked a trainable weight BF16. Codegen emitted a float* buffer, reported no skipped operations, and silently omitted the weight from parameter_gradient_order and optimizer updates. Storage admission now rejects unsupported tensor and reference dtypes before C emission. It also rejects inconsistent declarations, integer weights/gradients, and configurations claiming BF16 with FP32 tensors. The FP32 head author requires explicit FP32 arrays instead of interpreting packed uint16 weights as numeric FP32 values.

Released head weights: bounded FP32 training parity

The same canonical head topology now runs training at the released dimensions: 4,096-channel features, width 1,024, 16 attention heads, feedforward width 4,096, two evidence layers and four field layers. The head safetensors and independent reference source are checked against the pinned hashes before use. No kernel, derivative, compiler special case or numerical tolerance was changed.

Four native AdamW updates compare every effective parameter gradient, updated weight and optimizer moment against pinned PyTorch. On the fixed synthetic-feature request, loss falls from 0.59229439 to 0.13316447. Maximum absolute differences are 1.68e-7 for gradients, 9.54e-7 for weights and 2.36e-8 for moments. This measures arithmetic and state correctness, not downstream decision quality or generalization.

The fixture deliberately keeps backbone features and a small output-embedding table synthetic and frozen. It is released-head training with supplied features, not training with a generated backbone or reproducing the publisher's training data. FP32 AdamW uses the existing declared recipe: learning rate 0.001, epsilon 1e-4, weight decay 0.01, beta values 0.9 and 0.999.

A fresh subprocess loads the generated library, restores the checked checkpoint and executes the remaining native updates. Its loss sequence, final weight hash, optimizer-state hash and step count must exactly match uninterrupted execution. The existing same-process recovery, frozen-weight checks, rejection tests and separately generated inference export remain in place.

Complete head topology: FP32 training on frozen supplied features

The bounded experiment now derives the training graph from the canonical complete-head circuit: two evidence-routing layers, four field layers, and every scoring branch. The existing shared v7/v8 backward synthesizer, memory planner, generated C and native AdamW execute 144 forward operations and 494 backward operations. Python authors the graph and runs the independent oracle; it does not update CKE parameters. No Clef-name branch is added to generic lowering.

On the small geometry (six tokens, eight channels, two questions with two/one options), all 162 effective trainable parameter arrays are compared with the hash-pinned reference class using PyTorch autograd. Forty updates reduce loss from 0.28329045 to 0.06633431. Maximum absolute differences over the trajectory were 1.38e-6 for gradients, 1.67e-6 for weights, and 3.15e-7 for optimizer moments (PyTorch 2.12.1 CPU, seed 611). The test checks gradients, weights, optimizer moments, byte-identical frozen feature/embedding weights, rejection without updates, exact checkpoint resume, and trained-weight reload through a separately generated inference entry. This explicit epsilon limits amplification of roundoff-sized gradients on shift-invariant biases; it does not change the forward or gradient tolerance. The existing component recipes retain their own epsilon and remain separate regressions.

Reusable additions are checked indexed gather/scatter, explicit per-operation row counts for linear and add derivatives, generated integer metadata initialization checks, and opt-in contiguous flattening. The checked projection source is compiled with the generated library, using its existing scalar/AVX provider contract rather than changing global engine compiler flags.

The offline builder version/v8/decision/package_clef_head.py uses the ordinary circuit → map resolution → lowering → generated-C compiler. It packs effective FP32 weights and registered inputs; it performs no model arithmetic. Shared checked-graph build code now lives in version/v8/scripts/compile_checked_bundle_v8.py, with compatibility imports for existing tests. The worker uses only Python's standard library for request handling and byte copies; all head arithmetic remains in the generated entry. A subprocess test uses python -S to prove NumPy, safetensors and PyTorch are not runtime dependencies.

An administrator supplies a trusted package manifest and its expected SHA-256. This is executable native code, not an untrusted upload interface. The manifest binds the model revision, CKE revision, effective weights, circuit, layout, call IR, generated source, compiler/build identity, native library and registered feature files. The loader checks hashes, shapes, offsets, disjoint input/output/weight regions, finite features, token IDs, spans, final-valid-token selection, option counts and candidate ownership before loading C. On Linux, it loads the exact verified library bytes from a sealed memfd. Weights load once; each request clears non-weight arena regions and copies all of its registered inputs. The host does not schedule neural operations. Packages have one compiled geometry and at most 64 registered artifacts; runtime-variable feature shapes and arbitrary uploads are not supported.

Each registration contains hidden, input_ids, question_spans, option_spans, global_span, option_counts and question_type_ids, plus a selected question index and its stable candidate IDs. The entire multi-question context executes; one question's logits are returned. Reordering request candidate IDs only reorders those scores. Changing the head context requires a new registered artifact and hash. artifact_id in response evidence is the package SHA-256; ir_id is the call-IR SHA-256; library_sha256 identifies the loaded bytes. The input hash binds both feature bytes and the registration metadata. No host paths are returned.

The loopback worker allows one active evaluation, no evaluation queue and four connection threads. Concurrent evaluations return BUSY; excess connections close. A two-second absolute connection timer prevents slow clients from occupying threads indefinitely. Requests and responses remain bounded to 16 KiB, 16 candidate IDs and a maximum 1,000 ms consumer attempt. The worker checks expiration before and after native execution and before responding. The independent consumer rechecks the same absolute monotonic deadline inside its publication lock, after validation and lock wait. Cancellation/replacement invalidates pending results immediately. A disconnected or expired native call retains its slot and arena until C actually returns. Closing the worker joins handlers before unloading its library. Remote exposure, authentication and native interruption require separate contracts.

Indexed scoring gradients: separate normalization contracts

The final scoring branches now have checked FP32 derivatives for indexed pair features [a, b, a·b, |a−b|], normalized-vector dot products and cosine similarity. Owner indices route each option to its question. Repeated owners accumulate contributions; unreferenced owners receive zero. Both public gradient buffers are published only after all checks and reductions succeed. Caller-owned scratch holds groups·channels + 2·rows·channels floats; there is no kernel allocation.

Forward equivalence does not establish backward equivalence. The pinned head uses normalize-and-dot for its prior score and cosine_similarity for its joint score. PyTorch 2.12.1 normalization has a zero clamp derivative below epsilon, whereas its cosine implementation clamps a cloned norm under NoGrad and retains the norm derivative below epsilon. The new providers encode those policies separately. At zero norm, the norm VJP is zero; the direct numerator derivative still flows. At the normalization clamp boundary the derivative is one. Absolute difference uses zero subgradient at equality, including signed zero.

Consequently the cosine provider's below-clamp VJP deliberately matches the pinned framework's backward convention, not the finite-difference derivative of its clamped forward function. Central differences are tested away from nonsmooth/clamped boundaries; separate autograd tests cover zero, below epsilon, equality and adjacent FP32 values on both operands. Future head backward authoring must select the explicit derivative contract. Neither forward provider identity nor epsilon alone selects it.

Noncausal attention backward and native training

A bounded generic composition now trains through feature lookup → trainable projection → Q/K/V projections → full noncausal attention → residual → scores → cross-entropy. Automatic backward lowering declares every branch accumulation and native AdamW updates the selected parameters. The new provider handles unequal query/memory lengths, packed token-major heads and caller-owned scratch. It does not implement masking, dropout or BF16 attention backward.

Forward arithmetic remains FP64 ascending dot products with FP32 score/exponential stores. Backward recomputes those scores; dS stores FP32, dQ reduces FP64, and shared dK/dV accumulate in ascending query order with an FP32 store after each query. All three gradient outputs are staged until validation and arithmetic succeed. Scratch is Q·H·D + 2·S·H·D + 2·S floats.

The shared trainer now propagates map-declared zero-success status. A checked kernel failure stops the step before AdamW, leaves weights/moments untouched, clears the incomplete accumulation window and leaves the caller's loss output untouched. This is not general rollback for arbitrary void providers. The fixed-batch contract rejects partial batches rather than allowing padding into unmasked softmax; native kernel tests cover unequal Q/S, while the composed training fixture uses four tokens. Variable-length masked training remains a separate contract.

Cached-statistics LayerNorm training composition

The next trainable composition is fixed features → trainable projection → affine LayerNorm → trainable scores → cross-entropy. Existing native LayerNorm forward/backward arithmetic is reused; no new normalization kernel or model-specific compiler branch is introduced. The forward provider publishes its actual FP32 mean and reciprocal standard deviation, which automatic backward lowering passes to the existing VJP. Epsilon belongs to the operation, independently of the enclosing model.

Shared training code generation now accepts an opt-in, map-owned ABI for bounded contiguous FP32 buffers and literal scalar parameters. It rejects missing ports/providers, reordered ABIs, unsupported phases/dtypes, invalid scalars, insufficient capacities, incorrect shapes and writable aliases instead of guessing argument bindings. The selected maps participate in runtime/checkpoint identity. The legacy LayerNorm providers remain void: finite operands are their caller precondition. Checked providers now use the separate zero-success failure contract described above.
