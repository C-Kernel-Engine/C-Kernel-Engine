Question
--------
Can batched projection work retain the sequential decode attention reduction, and does that make batched prefill numerically equivalent to the safe sequential path?

Implementation
--------------
The Qwen4-Exp circuit requests f16_online_fp32_merge for its quantized FP16-cache batched prefill, the same reduction it requests for decode. The existing prefill provider map now declares batch_append in addition to segmented_append. The compiler resolves the provider explicitly and generated C calls attention_forward_causal_head_major_gqa_prefill_append_f16cache_contract_workspace. There is no HTTP, server, model-name compiler, or generated-source patch. The default bundle config still declares sequential_decode.
