Ming3 TTS: first generated flow arithmetic

Status: bounded FP32 arithmetic milestone. No Ming checkpoint execution, DiT, audio VAE, complete synthesis, sampled generation or serving capability is certified.

The model is inclusionAI/Ming-3.0-tts-0.5B. The publisher combines a Qwen2.5 backbone with a DiT flow head, an aggregator, an audio VAE and a speaker encoder. Existing CKE TTS work supplies reusable arithmetic and serving infrastructure, but does not certify this composition.

What executes

difference = prediction - null_prediction
velocity   = prediction + cfg * difference
euler      = latent + dt * velocity
output     = euler + noise_amplitude * supplied_noise

The circuit decomposes this into eight checked scale/sum operations through normal circuit resolution, kernel maps, memory planning, lowering and generated C. Providers are scale_vector_checked_f32 and audio_scaled_sum_strided_f32_checked. No new kernel, model-name compiler branch or handwritten neural executor is needed for this step.

All tensors and coefficients are supplied in the arena. The caller must set neg_one=-1; it is a supplied scalar, not a native constant validator. The supplied noise amplitude represents the publisher's noise coefficient at this step. Time schedules, CFG policy, random-number generation and BF16 storage rounding are not implemented by this entry. Intermediate buffers may change on failure; the final output remains untouched when an upstream operation rejects.

Audio decoder: checked linear interpolation

A reusable audio_upsample_linear_frames_f32_checked provider now implements offline integer-factor half-pixel interpolation with clamped endpoints. It consumes frame-major FP32 values, has explicit capacities, allocates no memory, and rejects invalid geometry, overlap and nonfinite inputs before output writes. The map declares FP64 coordinates and FP32 two-product/add arithmetic with no FMA. It does not implement streaming lookahead or BF16 storage conversion.

On 2026-11-14, an isolated publisher PyTorch 2.6.0 CPU run generated 112,896 finite samples at 44,100 Hz for “Hello. This is Ming speech.” using UK_George, seed 731, temperature zero, four threads, and a 128-step ceiling. The publisher run took 26.62 seconds including synthesis and WAV preparation; this is a reference-development observation, not CKE performance or listening approval. The publisher warned that SDPA sliding-window support was incomplete. Independent mask certification remains required.

The captured decoder FC1 output contained 32 × 896 values. Native factor-four interpolation matched all 128 × 896 FP32 reference outputs; rounding both results to BF16 also matched. A small cropped real-input fixture is retained for nightly. This is identical-input primitive evidence, not full-model parity. The generated regression checks normal map resolution, lowering, execution and rejection recovery; a nearest-neighbor negative control fails the intended value comparison.

Generated waveform from supplied spectra

The next connected boundary is an explicit-window inverse real DFT, normalized by overlap-add and cropped by caller-declared extents. Ming uses FFT length 3528, hop 882 and 1323 samples cropped at each end; Kokoro's centered crop is different. The new provider consumes Cartesian spectra and the actual stored window, avoiding an unannounced recomputation of upstream BF16 magnitude or phase.

Identical-input replay isolated a 0.002938 maximum difference to the window normalizer. The publisher squares its BF16 window and stores each fold addition in BF16. For each destination sample, CPU fold accumulates contributing frames in descending order. Reversing that order is numerically observable. The native contract now declares these conversion points and ordering explicitly.

On the retained 128-frame reference, normal generated execution produced 112,896 finite waveform samples. Maximum absolute error was 8.94e-8 and RMSE 6.80e-9 against the publisher waveform. The native final stage took 1.92 seconds with a 4,201,216-byte arena in one development run. This measures only waveform reconstruction from oracle spectra, not text-to-speech speed or listening quality.

This correctness provider uses an FP64 inverse-DFT recurrence and overlap numerator, then the declared BF16 envelope and FP32 output. It is quadratic in FFT length, not an optimized FFT implementation. NumPy FP64 supplies an independent reference; a wrong fold-order control must fail. Existing Kokoro ISTFT contracts and execution remain separate.

First complete DiT block, explicit FP32 composition

The generated first-block graph now connects RMSNorm, biased Q/K/V projections, consecutive-pair rotary embedding, full unmasked attention, output projection, residual addition, second RMSNorm and the GELU MLP. It reuses checked providers and adds a checked explicit-table pairwise rotation. Semantic checkpoints identify all fourteen operation boundaries for X-Ray.

Nonzero small graphs at two, three and seven tokens pass an independent reference. Corrupting a Q weight or a rotary coefficient fails the intended intermediate comparison. Invalid rotary input leaves the final output untouched; restoring valid input permits another successful call.

Both real first-block conditioning branches were replayed with the pinned weights and inputs recast to FP32. Compared with the publisher block also recast to FP32, maximum errors were 3.34e-5 and 5.34e-5, with RMSE 1.99e-6 and 4.83e-6. The report labels these measured differences, not certification. This graph does not implement publisher BF16 storage boundaries, the full eight-block DiT, timestep conditioning or the complete sampler. It accepts supplied rotary tables.
