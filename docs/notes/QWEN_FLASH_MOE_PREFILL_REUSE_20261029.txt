Qwen3.8 Flash Next routed-expert prefill reuse, 2026-10-29

Scope
-----
This is a new generated-runtime provider for Q4_K gate/up weights with
Q5_0 or Q8_0 down weights. It groups already-computed input rows by selected
expert inside each routing slot, packs that expert's gate/up weights once in
caller-owned per-worker scratch, and processes the bucket. A barrier between
slots preserves every token's original weighted-accumulation order. Sparse
buckets, small row counts, unsupported ISA, and insufficient reuse workspace
retain the existing parallel provider. Existing deployed bundles do not change
until rebuilt; a compatible rebuilt bundle selects the provider for prefill.
No recurrent update is reordered.

The pinned 8K Q4_K_M bundle resolves 24 Q5_0 and 24 Q8_0 reuse calls in
prefill; decode continues to resolve the original providers. The bundle was
generated from commit 796a87322 in an isolated worktree. No existing server
was replaced.

Limitations and next gates
--------------------------
This is one repeated-route candidate on one artifact, not a general prefill
speed certification. The 6,089-token runs remain about 4.1–4.5 times slower
than the earlier matched llama.cpp prefill (89.5 s); the run used the same
tokens but was not a same-window llama.cpp rerun. A sample during the new
long run attributed 48% of sampled CPU cycles to packed Q4_K projection work,
with about 15% still in packing in the existing fallback path. Sampled cycles
are not wall-time savings.

Before promoting this as a production serving speed claim: verify reset/repeat
and cancellation on the rebuilt bundle, repeat matched idle-host measurements,
and require final-head nightly. Keep a low-reuse case in regression coverage so
grouping overhead does not become a hidden regression.
