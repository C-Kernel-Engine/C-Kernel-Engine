Clef-Flash decision-head bring-up

Model topology lives in the circuit builders here. Kernels implement arithmetic; maps describe ABI, scratch and numerical contracts. Generic operation catalogue entries do not inspect the model name.

Complete bounded head forward pass

build_clef_flash_complete_head_circuit.py executes 140 operations in one generated entry: head ingress → two evidence-routing layers → option summaries → field assembly → four pre-norm self/cross-attention decoder layers → field/option normalization → prior, cosine and residual scoring → raw option logits. The host supplies hidden features, output-embedding rows, token IDs, checked spans, option counts and question types. It does not schedule the layers.

Question types index the released three-row type embedding. Consecutive option groups retain their question/option order; tests reorder entire questions with their option blocks and type identities. No softmax decision policy is imposed on the final raw scores. There is no generated-backbone or complete service certification in this milestone.

Six reusable checked operations close the scoring gaps: row broadcast addition, indexed pair features (left, right, product, absolute difference), indexed cosine reduction, clamped scalar exponential, stable scalar sigmoid and scalar vector multiplication. Their maps declare sizes, scratch, numerical semantics and status propagation. Generic compiler changes are operation catalogue entries only.

First generated backward composition

Three reusable FP32 vector-Jacobian products now cover token-span means, exact erf GELU, and grouped query-conditioned weighted pooling. They are backward providers, not inference aliases. Their maps own strides, capacities, scratch, numerical contracts and status propagation. The checked-call emitter now accepts an explicit backward phase and rejects providers used in the wrong phase. No model-name dispatch or second training workflow is introduced.

The model-neutral regression executes one generated forward entry for span pooling → erf GELU → grouped pooling, then one generated backward entry for the reverse chain. Only native-produced forward intermediates enter that backward entry. This is an explicitly authored VJP circuit, not automatic backward synthesis through cke.v8.compile. It does not contain trainable parameters, a loss, optimizer updates, or the remaining complete-head derivatives.

  • Span gradients sum all overlapping contributions in ascending span order with FP64 accumulation. Unreferenced valid tokens become zero; inactive token rows and padding remain unchanged.
  • Erf GELU uses its analytic derivative in FP64, distinct from the existing tanh-approximation derivative.
  • Grouped pooling differentiates both value and score paths, recomputing the forward provider's FP32 probabilities. Ordered FP64 reductions and explicit FP32 intermediate stores are declared in its map. The options and query gradients publish together only after all checks succeed.
  • Each VJP overwrites its valid output gradient. Overlapping contributions inside a VJP accumulate; fan-out across separate graph operations still requires an explicit gradient-accumulation operation.
  • All outputs and scratch must be disjoint from read buffers and one another. Scratch may change on rejection; that kernel's gradient outputs do not. A later operation failure can leave earlier graph intermediates written, so the entry status must be checked. Tests inject a final-operation failure and verify that the final token gradient remains untouched, then recover.

Tests cover independent ordered arithmetic oracles, optional PyTorch autograd, finite differences for both grouped-pooling inputs, unequal and singleton groups, padded strides, null/misaligned/overlapping regions, capacity and finite-overflow rejection, and A→B→A recovery. Generated execution and scalar oracles require no model assets or PyTorch. PyTorch absence is an explicit SKIP for the autograd comparison.

Earlier option-summary milestone

build_clef_flash_option_summary_circuit.py extends the canonical ingress and both evidence-routing layers through grouped option pooling and option_summary_norm. Its single generated entry executes 43 operations. Question option counts partition consecutive routed option rows. Each question's projected vector supplies its pooling query. Normalization declares epsilon 1e-5 locally, independently of the enclosing model configuration.

The grouped provider validates positive counts and exact coverage, finite valid inputs, physical strides, capacities, alignment and disjoint writable buffers. Caller-owned scratch stages the result, so rejection does not publish partial output. Read-only buffers may alias each other. Padding is neither consumed nor written. Arithmetic follows the registered ordered FP64 reductions with FP32 intermediate storage; no backward capability is advertised.
